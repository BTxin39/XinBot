# XinBot v0.1 使用手册

本手册对应 v0.1 网页界面。Windows 用户优先使用 PowerShell，所有安装、启动命令均在项目根目录执行，即包含 `pyproject.toml` 的目录。

## 1. 安装与首次启动

1. 解压 `XinBot-v0.1.0.zip`，进入解压后的 `XinBot-v0.1.0` 文件夹。不要直接在压缩包内运行。
2. 按 [uv 官方安装说明](https://docs.astral.sh/uv/getting-started/installation/) 安装 uv，安装后重新打开 PowerShell。
3. 在项目文件夹内打开终端，执行 `uv --version` 确认安装成功。
4. 执行以下命令，首次运行需要联网下载 Python 和依赖，可能耗时较长。

```powershell
uv sync --frozen
uv run xinbot start web
```

5. 保持该终端运行，在浏览器打开 <http://127.0.0.1:3796>。

后续也可在同一目录执行 `./start.ps1`。如果 PowerShell 提示禁止运行脚本，使用上面的两条命令即可，不必关闭系统执行策略。

发布 ZIP 已含构建好的网页，不需要安装 Node.js。它不是独立 EXE，仍需要 Python 3.12+ 运行环境及依赖；uv 可按项目要求管理 Python。

停止服务：回到启动终端按 `Ctrl+C`。关闭网页标签不会停止服务。再次启动仍使用原来的项目目录，以便读取原来的配置和记忆。

## 2. 分清三个“模型”概念

| 项目 | 作用 | 操作位置 |
| --- | --- | --- |
| 语言模型 | 生成聊天回复，例如云端模型或 Ollama 模型 | 设置 → 模型与连接 / 运行配置 |
| 角色卡 | 定义称呼、性格、场景、开场白 | 角色卡 |
| 桌宠外观 | 显示 Live2D 或 Codex 精灵动画 | 桌宠外观 |

导入 Live2D 不会自动配置聊天接口；导入角色卡也不会自动下载外观。没有外观时仍可先配置语言模型并聊天。

## 3. 云端 API：完成第一次聊天

1. 向你选择的服务商获取 API Key、OpenAI-compatible 接口地址及可用模型 ID。网页订阅不等于 API 额度，具体以服务商规则为准。
2. 点击左侧“设置”，选择“模型与连接”，向下找到“添加 / 更新连接”。
3. 按以下说明填写表单。

| 字段 | 怎么填写 |
| --- | --- |
| 接口类型 | 选择 `OpenAI Compatible` |
| 连接名称 | 自定标识，例如 `my-provider`；使用英文字母、数字、下划线或连字符 |
| 模型 ID | 服务商给出的准确 ID，不是随意起的显示名称 |
| API Base URL | 服务商文档提供的 HTTPS API 基地址，通常以 `/v1` 结尾；不要填网页聊天地址或完整 `/chat/completions` 路径 |
| API 密钥 | 只填密钥本身，不添加 `Bearer `、引号或换行 |

4. 点击“保存连接”。保存成功表示配置已登记，不代表已测试额度或模型访问权限。
5. 切换到“运行配置”，在“语言模型”中选中新模型，点击“应用设置”。**只保存连接不会自动切换当前聊天模型。**
6. 点击左侧“角色卡”，为想使用的角色点击“开始对话”。
7. 点击左侧“对话”，输入“你好，请介绍一下自己”，点击发送按钮，等待回复。

若失败，先核对 Base URL、模型 ID、密钥权限和账户额度。不要在反馈截图或日志中公开真实密钥。

### 增加、切换和删除语言模型

同一服务商增加模型：在“模型库”下选择“模型所属连接”，填写“模型 ID”，点击加号。随后到“运行配置”选择它并应用。

删除模型：点击该模型行的垃圾桶图标。当前正在使用的模型不可删除，先切换到另一个模型。

删除整个服务连接：先切换到其他连接的模型，再删除该连接下所有模型，最后点击连接行的“删除连接”图标。删除连接会同时尝试删除其本机密钥。

### 更新和删除 API Key

1. 在“服务连接”中，将鼠标停在图标上查看操作名称。
2. 点击“更新密钥”，填写新密钥，再点击“更新密钥”保存。页面不显示旧密钥。
3. 点击“删除密钥”并确认，可删除本项目 `.env` 中的对应项；需要密钥的连接之后将无法正常调用。

编辑已有连接时，密钥留空表示保留旧值，不是清空。更换接口地址或类型必须重新输入密钥，避免旧密钥被发送到其他地址。

密钥保存在本机明文 `.env`，不要上传、分享或放进公共同步目录。不要把 Key 填进 URL、角色卡或聊天框。系统环境变量里另行设置过的 Key，必须在系统设置中另外删除。

## 4. Ollama：使用本机语言模型

本节为操作步骤；开发环境未安装 Ollama，只做了模拟协议测试，尚未验证真实本机推理。

1. 从 [Ollama 官方网站](https://ollama.com/download) 安装适合系统的版本。
2. 打开 PowerShell，运行 `ollama list`。如果提示无法连接，启动 Ollama 应用，或在一个终端运行 `ollama serve` 并保持它运行。已有服务时不必重复启动。
3. 安装一个适合电脑内存和显存的模型，例如在另一个终端执行：

```powershell
ollama pull qwen3:8b
ollama list
```

示例会下载模型权重，需要网络与足够磁盘空间。内存不足时选择更小的模型，不必照搬 `8b`。

4. 回到 XinBot 的“设置 → 模型与连接 → 添加 / 更新连接”。
5. 接口类型选 `Ollama · 本机`，连接名称填 `local-ollama`，保留 `http://127.0.0.1:11434/v1`。
6. 点击“读取本机模型”，在“已安装模型”中选择一个模型，点击“保存连接”。Ollama 无需填写真实 API Key。
7. 在“运行配置”选择刚登记的模型，点击“应用设置”，再回到“对话”发送消息。

“读取本机模型”只列出已安装模型，不负责下载。网页删除模型也只移除 XinBot 登记记录，不会删除 Ollama 权重。XinBot 目前只接受本机 Ollama 地址；工具调用还需要模型本身支持。

## 5. 安装和更换桌宠外观

### 先使用官方 Haru 测试模型

在项目根目录的另一个 PowerShell 窗口运行：

```powershell
uv run python scripts/download_live2d.py
```

下载完成后刷新网页，点击左侧“外观”，在“桌宠外观”中选择 Haru。该脚本同时获取 Live2D 所需的 Cubism Core。下载失败时查看终端错误，不会影响纯文字聊天。

第三方模型与 Core 未包含在发布 ZIP 中。下载、使用和再次分发前须核对各自授权。

### 导入自己的模型

1. 准备完整 ZIP：Live2D 包需要 `.model3.json`、对应 `.moc3`、纹理及清单引用的动作等文件，保留原有相对目录结构。仅上传模型图片不能变成 Live2D。
2. 点击“桌宠外观 → 导入 ZIP”，等待成功提示。
3. 点击模型条目切换外观。选择结果会绑定当前角色；也可在角色编辑页通过“绑定外观”选择。

Codex 精灵包需要 `pet.json` 和它引用的精灵图，当前适配固定 8 列 × 9 行布局。测试目录 `pet/codexpet/kaguya` 存在时会被扫描；也可把包含 `pet.json` 的完整文件夹压成 ZIP 后导入。

包大小上限 64 MB。当前不支持旧版 `.model.json` / `.moc` 的 Cubism 2 模型。模型不能显示时，检查资源是否齐全、路径大小写是否一致、浏览器是否启用硬件加速。

左侧桌宠底部工具提供缩放、重置、暂停和打招呼等操作，悬停图标可查看名称。v0.1 是浏览器内桌宠，不是系统桌面透明悬浮窗。

## 6. 新建和导入酒馆角色卡

1. 点击“角色卡 → 新建”。
2. 填写“角色名称”，按需选择“绑定外观”。
3. 初次使用先填写“角色描述”“性格”“场景”“开场白”，其他高级字段可留空。
4. 点击“保存角色卡”，然后在角色库中点击该角色的“开始对话”。

可用以下内容体验：

| 字段 | 示例 |
| --- | --- |
| 角色名称 | 小新 |
| 角色描述 | 一位帮助用户安排日常学习的桌面伙伴。 |
| 性格 | 温和、直接，回答简洁，不虚构已经完成的事情。 |
| 场景 | 用户正在书桌前准备今天的学习计划。 |
| 开场白 | 今天想先完成哪件事？ |

已有角色卡：点击“导入”，选择 Character Card V2 JSON 或包含角色卡元数据的 PNG。普通头像 PNG 不等于角色卡。

修改角色：点击“编辑”后保存。导出使用下载图标，输出 JSON；删除使用垃圾桶图标。内置角色不可删除，当前角色需先切换后再删除。

开场白只在空会话初始化时添加，修改开场白不会替换已有历史。世界书和未知扩展会被保留，但 v0.1 不执行完整酒馆世界书规则，也不会自动运行卡片脚本。

## 7. 记忆管理与交互终端

### 用网页管理

1. 点击“记忆 → 记忆库”，输入名称，例如 `study`，点击加号创建。名称只能包含字母、数字、下划线或连字符。
2. 点击该记忆右侧的播放图标切换；出现“当前”后，后续聊天使用该会话。
3. 点击记忆名称，打开编辑区，可查看消息并修改用户称呼、关系阶段、重要事实、用户偏好和长期摘要。
4. “重要事实”每行一条；“用户偏好 JSON”必须为合法 JSON，键和值使用字符串，例如：

```json
{"language": "中文", "reply_style": "先结论后解释"}
```

5. 点击“保存长期记忆”。需要备份时点击“导出记忆”下载 JSON。

“清空消息记录”会删除此会话的消息，但保留长期记忆。删除整个记忆前，必须先切换到其他记忆。破坏性操作需确认，无法撤销；当前网页只提供导出，没有记忆文件导入功能。

切换角色时会自动选择该角色的默认记忆，如需继续 `study`，请在切换角色后重新选择它。记忆窗口不是无限历史存档，超出窗口的旧消息会被裁剪，运行摘要目前不跨重启保存。

### 用交互控制台管理

点击“记忆 → 交互控制台”，在底部输入框一次输入一行，按回车或点击执行按钮。这里是 XinBot 记忆命令，不是 PowerShell，无需额外安装终端软件。

```text
help
list
create tutorial
use tutorial
describe tutorial "使用教学测试会话"
show tutorial
clear tutorial
use default
delete tutorial
```

按顺序执行即可体验创建、切换、描述、查看、清空和删除。`clear`、`delete` 会弹出确认框；若 `tutorial` 已存在，请换一个新名称。最后删除前切回 `default`，避免删除当前记忆被拒绝。

上下方向键可选历史命令。不支持 `cd`、`pip`、`ollama`、PowerShell 或任意 Python，系统命令请到真正的本机终端运行。

## 8. 图片转字符画

1. 点击左侧“字符画”，再点击“选择图片”，选择 PNG、JPEG 或 WebP。
2. “字符集”选择 `Braille 点阵` 或 `ASCII 文本`，调整宽度。首次建议保留 60 字符。
3. 点击“转换”，下方显示结果。
4. 使用复制或下载图标获取文本。查看时选等宽字体，避免字符错位；Braille 还需要字体支持盲文字符。

图片上限 10 MB、1600 万像素。转换使用临时文件，不会把原图保存到角色库。它对应 `app/cli/image_to_ascii.py`，不能将图片转换成可动 Live2D。

## 9. 知识库与配置

知识库：点击“知识库 → 导入文档”，初次可用少量 TXT 或 Markdown；也可填写网页地址并点击“导入网页”。导入后，在搜索框输入相关问题查看匹配内容。首次嵌入可能需要联网下载 Chroma 默认模型。

知识库用于文档检索，记忆用于会话和用户资料，二者不是同一份数据。垃圾桶可删除单个知识源，“清空知识库”删除全部知识源，操作前先备份原始文件。

“设置 → 运行配置”可修改语言模型、温度、记忆消息数与网页搜索开关，点击“应用设置”保存。开启网页搜索不代表已验证外部搜索服务可用性。

### 更改 Web 端口

1. 将“Web 端口（重启后生效）”改为一个未占用的端口，例如 `4000`。
2. 点击“应用设置”。此时当前网页仍在旧端口，不会立即跳转。
3. 在运行后端的终端按 `Ctrl+C` 停止，然后重新执行 `uv run xinbot start web`。
4. 打开 <http://127.0.0.1:4000>，更新收藏夹。

临时指定端口也可运行 `uv run xinbot start web --port 4000`，命令行参数优先于保存配置。只允许本机监听；不要为远程访问随意开放防火墙或转发端口。

## 10. 常见问题与备份

| 现象 | 处理方法 |
| --- | --- |
| `uv` 无法识别 | 安装 uv 后重新打开终端，确认 `uv --version` 成功 |
| 网页打不开 | 确认后端终端仍运行，使用 `http`，核对是否修改端口；端口占用时用 `--port` 换一个 |
| 源码启动后网页为空或 404 | 发布 ZIP 已含前端；Git 源码则需按 README 的开发步骤执行 `npm ci` 和 `npm run build`，不要用 `--dev` 单独启动生产网页 |
| 保存连接了却仍用旧模型 | 在“运行配置”选择新模型并点击“应用设置” |
| 密钥被拒绝 | 去除 `Bearer `、引号、空白和换行；确认粘贴的是 Key 而非整段命令 |
| 提示需重新输入密钥 | 更换了接口地址或类型，这是防止旧 Key 被转发的保护措施 |
| Ollama 读取失败 | 在系统终端检查 `ollama list`；确认服务运行、地址为本机、端口默认 11434 |
| Ollama 没有可选模型 | 先在系统终端 `ollama pull` 下载，再点击“读取本机模型” |
| 桌宠区域没有模型 | 发布包不带第三方模型，先下载 Haru 或导入完整外观 ZIP |
| 无法删除模型、角色或记忆 | 先切换到其他项；内置角色始终不能删除 |
| 控制台提示未知命令 | 输入 `help`；此处只能管理记忆，不能执行系统命令 |

迁移或升级前先停止服务，再私下备份根目录 `.env`、整个 `data/` 和 `pet/`。所有桌宠资产统一存放在 `pet/`：`live2d/` 存放 Live2D 模型，`codexpet/` 存放 Codex 精灵包，`imported/` 存放网页导入包，`vendor/` 存放 Cubism Core。旧版本的 `app/web/static/models/`、`app/web/static/vendor/`、`data/web_uploads/pets/` 应分别迁移到这些对应目录，保留内部相对路径；遇到同名文件先比较备份，不要直接覆盖。其中可能包含密钥和个人对话，禁止提交到公开仓库或放入公开发布包。

新版本先解压到另一个目录并阅读变更说明，不要直接覆盖唯一备份。v0.1 发布包只含程序和公开默认角色，不含你的个人数据。
